### BUG-MTU-001 ｜ MTU 探测 TTL 硬编码为 1，跨网关目标必然失败且术语颠倒

- **模块**：18 合 1 工具箱·MTU 探测 ｜ **严重程度 S3** ｜ **优先级 P2** ｜ **状态 open**
- **证据等级**：L3 可复现 ｜ **复现率**：always（必现） ｜ **证据**：EVD-MTU-PING-003、EVD-MTU-SRC-004 ｜ **关联**：RM-TOOLS-010、TC-MTU-062
- **环境**：Windows / .NET 8 / net8.0-windows / v1.4.3
- **前置条件**：使用 MTU 探测，目标为任意跨网关地址（默认 8.8.8.8）
- **复现步骤**：
  1. 打开 18 合 1 工具箱 → MTU 探测，目标保持 8.8.8.8，开始探测；
  2. 二分负载 68–1500 均以 `new PingOptions(1, dontFragment: true)` 发送（`MoreViewModel.cs:203`）；
  3. 命令行对照：`ping -i 1 8.8.8.8` 与 `ping -i 30 8.8.8.8`。
- **实际结果**：所有探测包在第一跳网关即 TtlExpired，SuccessCount 恒 0，最终"未找到可用 MTU"。实测 `-i 1` 返回网关 `TTL expired in transit`，`-i 30` 正常收到 8.8.8.8 应答（TTL=107）。另 `:209` 把 ICMP 负载标为"路径 MTU"、负载+28 标为"IP MTU"，术语颠倒。
- **预期结果**：TTL 应足够大（如 64，路由追踪上限 30 跳）到达目标，再按 DF 二分得到正确路径 MTU；文案术语正确（负载+28 才是路径/IP MTU）。
- **影响**：默认目标下 MTU 探测完全失效，无法排查 PPPoE/隧道 MTU；同网段目标 1 跳可达而表现正常，具迷惑性。不影响主测速与其它工具。
- **根因分析**：
  - classification：logic_error；
  - trigger_hypothesis：以同网段/网关（1 跳可达）调试时，将路由追踪式递增 TTL 与 MTU 探测混淆，误固定 TTL=1；
  - change_correlation：v1.4.3 现存，未做 git bisect；
  - blast_radius：仅 MTU 探测；
  - confidence：high。
- **规避/修复建议**：`PingOptions` 首参改为固定较大值（如 64）；修正文案术语；修复后启用 Skip 用例 `MtuProbe_UsesTtlLargeEnoughToReachRemoteTarget`。

- **影响**：远程可写入 UI 无法表达的值；testTimeoutSec=5 小于默认 10s 平均窗口，可能产出无平均速率的结果。界面滑块操作不受影响。
- **根因**：boundary_mismatch，后端常量与滑块/文档分别维护、调整未同步；confidence high。
- **建议**：统一常量（建议以 UI/README 为准：testTimeoutSec 10–600、threadRampUpMs 0–2000），对 timeout<平均窗口增加校验；加 API↔XAML 范围一致性测试。

### BUG-FW-006 ｜ 防火墙入站规则添加为死代码，只删不建，就绪状态恒真

- **模块**：Web 服务器·防火墙 ｜ **S3 / P2** ｜ **状态 open** ｜ **证据 L2**（EVD-FW-006）｜ **关联**：RM-FW-016、TC-WEB-082
- **前置**：启用局域网 Web，存在防火墙且无同名放行规则。
- **实际**：`WebServerService.cs:513-524` `EnsureFirewallRule` 内层 try 执行 `delete rule` 后于 `:519` 无条件 `return`，`:523` 的 `add` 入站规则不可达；调用处 `:454` `_firewallReady=true` 恒成立；全仓检索 FirewallReady 无 UI/前端消费者（仅 status JSON 输出字段）。
- **预期**：真正探测/创建入站放行，或在无提权时返回未就绪并给指引；不应只删不建、误报就绪。
- **影响**：局域网首次访问可能被防火墙拦截而软件误报已就绪；反复启动会删除同名规则却不恢复。回环监听不受影响、无崩溃。
- **根因**：dead_code_logic_error，疑似因非管理员 `netsh add` 抛错而临时 `return` 屏蔽，却保留 delete 并置状态为真；confidence high。
- **建议（需作者定 UAC 策略）**：①delete 后正常 add，非提权失败时 `_firewallReady=false` 并给提权/手动指引；或②移除死代码与误导状态，文档改为提示手动放行。

### BUG-BW-004 ｜ 带宽换算不拒绝 0/负数

- **模块**：工具箱·带宽换算 ｜ **S4 / P3** ｜ **状态 open** ｜ **证据 L2**（EVD-TOOLBOX-009）｜ **关联**：RM-TOOLS-010、TC-NETSPEEDTEST-063
- **步骤/实际**：输入 0 → `seconds=size*8/0=double Infinity` 显示"∞ 秒"；输入负数 → 负耗时（`MoreViewModel.cs:409`）。
- **预期**：提示"请输入大于 0 的带宽数值"，不换算。
- **影响**：异常输入显示荒谬结果，无其它副作用；正数路径正确。
- **根因**：input_validation_missing，仅 TryParse 未校验正数域；confidence high。
- **建议**：TryParse 后增加 mbps<=0 分支；修复后启用 Skip 用例 Bandwidth_Zero/Negative。

### BUG-SUBNET-005 ｜ 子网计算不校验掩码连续性

- **模块**：工具箱·子网计算 ｜ **S4 / P3** ｜ **状态 open** ｜ **证据 L2**（EVD-TOOLBOX-009）｜ **关联**：RM-TOOLS-010、TC-NETSPEEDTEST-064
- **步骤/实际**：IP 192.168.1.1、掩码 255.0.255.0（位不连续），仍按字节 popcount 算出 CIDR=16 与网络/广播地址（`MoreViewModel.cs:375-394`）。
- **预期**：检测掩码必须为前导连续 1，非法时提示"无效的子网掩码"。
- **影响**：错误掩码下输出看似合理实则错误的网络参数；合法掩码计算正确。
- **根因**：input_validation_missing，未做 `(mask & (mask+1))==0` 连续性校验；confidence high。
- **建议**：增加掩码连续性校验；修复后启用 Skip 用例 Subnet_NonContiguousMask。

### BUG-FALLBACK-007 ｜ 内嵌兜底页未携带令牌，wwwroot 缺失时局域网全 401/403

- **模块**：Web 服务器·兜底页 ｜ **S4 / P3** ｜ **状态 open** ｜ **证据 L2**（EVD-FALLBACK-007）｜ **关联**：RM-FALLBACK-017、TC-WEB-040
- **前置**：wwwroot 缺失回退到内嵌 DefaultIndexHtml，且从非回环设备访问。
- **实际**：`:1844` 虽注入 `<meta name="nst-token">`，但 `:1885` `api()` 直接 fetch 不注入头，`:1900` startTest 仅带 Content-Type、`:1902` stopTest 无头；非回环 GET status/adapters/history 返回 401、POST 返回 403，页面打开但数据空、操作失败。
- **预期**：与正式 web.js 一致，从 meta 读取 token 并为所有 /api 请求附加 X-NST-Token。
- **影响**：仅 wwwroot 缺失的边缘场景下局域网远程控制不可用；回环免令牌仍可用，正式前端存在时不触发。
- **根因**：missing_auth_header，精简手写兜底页遗漏令牌注入；confidence high。
- **建议**：兜底页 api() 注入 meta 中的 X-NST-Token；补兜底页令牌头自动化断言。
